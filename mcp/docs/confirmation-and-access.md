# 确认与设备访问

MCP 工具在两种情况下**不会执行动作**，而是返回一个需要用户处理的地址。
两者的页面、语义和后续行为都不同，不能互相替代。

## DEVICE_ACCESS_REQUIRED（设备访问未满足）

- 含义：动作没有执行，设备访问密码尚未满足。
- 正确做法：把返回的 `authorizationUrl` 交给用户。它指向 `/#/devices`，页面有密码输入框。
- 完成后：用户在该页面完成授权，然后重试原调用。
- 禁止：不要重试、不要改道其它工具、不要绕过。
- 不要用 `confirmUrl` 代替：`/#/tool-confirm` 只拿一次性设备 token，无法完成设备授权。

## PENDING_CONFIRMATION_REQUIRES_V5（动作待确认）

- 含义：动作没有被执行，等待用户在 V5 页面确认。
- 正确做法：把返回的 `confirmUrl` 交给用户，说明需要在该地址完成确认。
- 完成后：用户确认后重试，或按返回的说明继续。
- 禁止：不要重复调用同一工具。

## 转达地址的格式要求

`authorizationUrl` / `confirmUrl` 必须可点击：用 Markdown 链接语法 `[打开 V5 页面](URL)` 或裸 URL 输出。
**不要**用代码块或行内代码包裹 —— 代码块里的 URL 不会渲染成可点击链接，用户只能手动复制粘贴。

## 确认结果语义

| 结果 | 含义 | 后续 |
| --- | --- | --- |
| `USER_DECLINED` | 用户已明确拒绝 | 不要重试 |
| `USER_CANCELLED` | 用户未做决定，动作仍待确认 | 等用户决定 |
| `PENDING_CONFIRMATION_REQUIRES_V5` | 动作仍待确认 | 把 `confirmUrl` 交给用户 |

## 客户端权限档位决定确认通道

- Codex Desktop 选**请求批准**：弹出就地确认卡，由用户当场决定。
- Codex Desktop 选**完全访问**：客户端直接短路 elicitation（用户看不到确认框），
  此时 MCP 按预授权自动向 V5 确认执行并返回成功。**不要把它当作用户拒绝。**
- 只有 `message` 出现"已按配置要求人工确认"时，才需要把可点击的 `confirmUrl` 交给用户。
