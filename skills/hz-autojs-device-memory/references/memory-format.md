# 手机本地操作记忆格式

本文件是 `/sdcard/appSync/memory/` 的唯一格式与更新协议。内置 Web AI、手机 AI 与插件设备入口共用这一协议。记忆是可选辅助，稳定执行不得依赖先读记忆。

## 固定位置与边界

- 记忆根目录：`/sdcard/appSync/memory/`
- 短索引：`/sdcard/appSync/memory/index.md`
- 详情：`/sdcard/appSync/memory/<slug>/SKILL.md`
- 索引中的路径必须是相对于 `index.md` 所在目录的 `./<slug>/SKILL.md`。不得指向该目录外，不得包含绝对路径、URL、`..`、符号链接目标或其他设备路径。
- 记忆文件的持久化位置只在当前目标手机，不建立服务器记忆副本或复制到另一台设备。命中的文本可经现有工具结果参与当前模型请求；已有会话、工具审计的行为不因本技能改变。
- 手机 AI 的 `phone.file.*` 只能在当前配置的 `runtimeCapabilitySnapshot.workspace.root` 内工作。固定目录不在该根内、被拒绝或不可用时，报告边界并停止记忆读写，不寻找替代存储位置。
- 只允许保存应用、版本、页面、执行模式/通道、素材 ID、适用/失效条件、失败码和证据摘要。图片、截图、色组正文、可执行流程、完整节点树和完整日志不属于记忆内容。

## 按需读取顺序

1. 只有在复用已验证事实、排查重复失败或核对反例时，才读取 `/sdcard/appSync/memory/index.md`；普通稳定执行直接使用当前设备证据。
2. 从索引匹配摘要声明的 `app`、`version`、`page`、`mode`、`channel`、`materialId` 条件。只记录影响复用的条件：设备级经验可明确写 `app=不限; page=不限`，不强行限定某个应用。版本范围已明确写出的，可按范围判断；必要条件未知时先核实，不把未知值当作不限。
3. 匹配后只读取命中项指向的 `./<slug>/SKILL.md`。多项命中时只读符合当前条件的详情，优先选择条件更具体、证据更近且没有已知反例的那项。
4. 没有命中时按普通探索/操作继续，不读取其他详情。
5. 索引返回真实“不存在”时记作无经验。权限拒绝、路径越界、设备离线、超时、任务失败或索引截断都不能解释为无经验。索引截断时停止匹配、读取详情与写入，报告读取上限；不能只根据可见前缀选择经验，或重复同一请求假装取得完整基线。
6. 记忆只提供候选事实。使用前重新观察当前页面、执行模式、通道和权限；若前置条件已变，按失效条件处理。记忆读取失败不得阻塞不依赖它的稳定执行。

匹配维度：

| 字段 | 记录内容 | 匹配规则 |
| --- | --- | --- |
| `app` | 稳定包名；设备级方法写不限 | 声明包名时必须相同；名称不能跨同名应用猜测 |
| `version` | 影响复用时记录已验证版本或明确范围 | 声明限制时当前版本必须在范围内；未知先核实 |
| `page` | 稳定页面名、页面类型或状态标识；设备级方法可不限 | 声明限制时当前页面/状态必须对应；不使用一次性动态文本 |
| `mode` | 如 `AUTO`、`ACCESSIBILITY`、`PRIVILEGED` 或当前产品定义的模式值 | 声明限制时必须与当前设备执行模式相同 |
| `channel` | 如节点、OCR、图色、特权通道等实际通道 | 必须与当前可用通道相符；降级不代表等价 |
| `materialId` | 已在本机创建且经过验证的图片或色组素材 ID | 声明时必须与当前素材库中的 ID 相同；素材本体始终留在素材库，不写入记忆 |

未知的必要条件可在当前设备上查明后再判断；不要为了命中而放宽条件。摘要只写最小事实与结果，不写步骤或可执行流程。

## 短索引模板

每个条目只保留“路径 + 一行适用摘要”，不放步骤、错误日志、证据正文或大量关键词。

```md
# 当前设备操作记忆索引

本文件只索引 `/sdcard/appSync/memory/` 内的技能式记忆，仅适用于当前设备。

<!-- memory-index-start -->
- [示例应用-设置页已知限制](./example-app-settings-fact/SKILL.md) — app=com.example.app; version=1.2.3; page=settings; mode=PRIVILEGED; channel=NODES; materialId=none; summary=原控件操作失败码 NODE_NO_EFFECT，已验证相邻祖先可操作
<!-- memory-index-end -->
```

索引约束：

- 一项一行；链接目标只用 `./<slug>/SKILL.md`。
- `summary` 是一句适用摘要，不是执行步骤或日志。
- 保持摘要精简，使索引完整内容处于当前工具读取上限内；超过上限时报告不能完整读取，不扩展其他存储通道。
- 同一 `slug` 只保留一个条目。
- 保留 `<!-- memory-index-end -->` 作为新增条目的唯一精确锚点。
- 已有索引缺少结束标记时，不要猜插入位置；先完整重读，保留全部内容，再加标记和条目后整文件写入，并读回验证。

## 详情模板

详情的 YAML frontmatter 只使用标准 `name` 和 `description`。`name` 必须与目录 slug 一致；`description` 用一句话写清应用、版本、页面、执行模式、通道与最小结果事实。

```md
---
name: example-app-settings-fact
description: "com.example.app 1.2.3 的 settings 页面在 PRIVILEGED/NODES 通道下，原控件操作失败码为 NODE_NO_EFFECT。"
---

# 示例应用设置页最小事实

## 最小事实

- 应用：com.example.app
- 版本：1.2.3
- 页面：settings
- 执行模式：PRIVILEGED
- 操作通道：NODES
- 素材 ID：none
- 失败码：NODE_NO_EFFECT
- 适用/失效条件：见下一节

## 证据摘要

- 验证时间：记录到日即可。
- 前态：可观察的起始状态。
- 动作后状态：证明目标已生效的页面、节点、OCR 文本或数值变化。
- 结果：例如操作完成、任务终态或目标资源增量。
- 只写摘要，不存截图、图片、色组正文、完整日志、完整节点树或可执行流程。

## 适用和失效条件

- 适用：再次列出应用、版本或范围、页面、执行模式、通道与必要前置条件。
- 失效：应用升级、页面改版、模式或通道变化、权限变化、控件语义不再唯一、已知反例出现时，停止复用并重新验证。
- 新反例推翻旧结论时，在同一详情内修正事实和失效条件，不创建重复记忆。

## 复用边界

- 本记录不包含可执行步骤；每次执行仍以当前页面观察和工具结果为准。
- 视觉素材只引用素材 ID，素材本体保留在统一图色目录，不进入记忆。
```

## 保存触发与顺序

在以下情况可保存最小事实，不等待用户另行要求：

- 常规方法失败后确认了稳定失败码或可复用的失效条件。
- 验证了可复用的素材 ID，且其适用条件无法从当前页面直接推断。
- 旧记忆在本设备出现反例，需要修正适用或失效条件。

不要保存普通一次性动作、未经效果证据确认的猜测、可执行流程、视觉素材本体、纯环境噪声或可能泄露隐私的页面内容。记忆写入工具自身需要用户确认时，仍按现有门禁执行。

1. 生成或更新 `<slug>`：只用小写字母、数字和连字符，建议为“应用或稳定简称-页面-方法”。
2. 与已命中详情比较；同一问题和相同适用条件优先更新原文件，页面相同但问题不同可以各建一项。
3. 创建或更新详情。创建详情前才建立 `/sdcard/appSync/memory/` 与 `/sdcard/appSync/memory/<slug>/`，不预先创建空目录或空索引。
4. 等待写入任务成功，再读取详情并逐项核对 frontmatter、声明的适用条件、失败、方法、证据和失效条件。
5. 详情读回成功后，重读 `index.md`。如果索引不存在才新建；如果存在就保留所有已有条目，替换同 slug 条目或向结束锚点前合并一项。
6. 写入索引后再次读取，确认本项路径、摘要和所有旧条目仍在。只有这一步通过才能报告“本机记忆已更新”。
7. 任一步冲突、截断、读回不一致或权限不足时停止，说明未完成位置。不要静默覆盖，也不要把详情当作已建索引。

## 三端文件工具协议

### 手机 AI

当前工具面的模型可见函数名以下方逐项列表为准；`phone.file.*` 是对应 canonical/日志名，不能把日志名当作可调用函数。

- `mobile_tool__phone_file_list`：`path` 必填；可带 `limit`，下一页必须等待并使用返回的 `cursor`。
- `mobile_tool__phone_file_read`：读取文本并返回当前 `sha256`。先读详情或索引再决定是否写入。
- `mobile_tool__phone_file_mkdir`：只创建一个目录；父目录必须已存在，目标必须不存在。创建记忆根和 slug 目录要按层级依次等待结果。
- `mobile_tool__phone_file_write`：`CREATE` 用于目标不存在，`expectedSha256` 必须为空；`REPLACE` 用于目标已存在，`expectedSha256` 必须是刚读到的当前摘要。
- `mobile_tool__phone_file_patch`：用刚读到的 `sha256` 作为 `expectedSha256`；`replacements` 一次提交所有互不重叠的精确替换。目标文本必须在文件中唯一。
- 哈希不匹配就停止当前写入，重读后重新生成合并内容；不要盲目重试。
- 不使用 shell、临时代码或泛化 executor 代替这些文件工具。

### Web AI

使用已核实的设备原生文件工具：

- `file.device.list`：`deviceId` + `path` 查看目录；需要限制返回时使用工具 schema 的分页/过滤字段。
- `file.device.readText`：`deviceId` + `path` 读取；`truncated=true` 时不能安全合并或覆盖。
- `file.device.writeText`：`deviceId` + `path` + 完整 `content`。该 schema 是整文件写入且没有哈希前置，必须在写前即时重读、合并全部已有内容，写后立即读回。
- 重读和读回不能消除并发覆盖；发现其他任务同时维护该文件或读回丢失旧条目时停止并报告，不宣称具有原子更新保证。
- `file.device.operation`：建目录使用已核实的 `operation: "MKDIR"`。不存在名为 `file.device.mkdir` 的工具。
- 局部补丁若由当前运行环境单独提供，只能在重新核对其实时 schema 和可验证的并发校验字段后使用；否则按“重读、完整合并、写入、读回”处理。
- 提交文件任务后，以任务实际终态作为写入成功条件；只看“已提交”不算成功。

### 插件

使用已核实的 MCP 文件工具：

- `device_file_list`：`deviceId` + `path`；可用 `directoriesOnly`、`nameContains` 缩小范围，并遵守分页结果。
- `device_file_read_text`：读取索引或详情。单次最多返回 12000 字符；`truncated=true` 时禁止无基线的合并覆盖。
- `device_file_operation`：建目录使用已核实的 `operation: "MKDIR"`；不要猜未核实的枚举值。
- `device_file_write_text`：整文件写入，MCP schema 没有 `expectedSha256`。写前即时重读，写后等待任务终态，再用 `device_file_read_text` 读回。
- 插件可能要求设备级授权或确认卡。拒绝、待确认、离线或失败都按真实状态报告，不换工具绕过。
- 不使用脚本、shell 或泛化任务工具作为文件读写后门。

## 隐私与复用边界

- 不保存账号、密码、访问 token、设备密码、验证码、密钥、聊天内容、通讯录、订单、医疗信息或其他个人数据。
- 不保存图片、截图、色组正文、视觉素材本体、可执行流程、完整页面文本、完整布局树或完整日志；用最少可观察条件概括证据。
- 不保存可复制的业务数据样本。将应用名、页面名、控件语义和结果抽象到下一次判断所需的最小程度。
- 记忆不承载代码、命令或可执行步骤；每次执行仍调用现有受控工具并遵守当前权限。
- 记忆不能证明其他设备、其他版本或其他执行模式可用。条件不符时重新探索，不把本机经验提升为全局事实。
- 稳定执行不得依赖本机记忆；记忆不可读、未命中或过期时，按当前设备证据正常继续。
