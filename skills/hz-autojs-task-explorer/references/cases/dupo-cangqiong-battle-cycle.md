# 斗破苍穹战斗循环案例

> 坐标说明：下文绝对坐标是 **1080×1920 基准空间** 的标定值，用于复算 `dx/dy`，**不是**可跨设备复用的像素。移植时按 `multi-resolution-adaptation.md` 改写成坐标契约。

- 类型：画布 / 自绘型，多状态战斗流程
- 设备：`device_android_e3bf91f528e0bbfe`
- 画布：1080×1920，竖屏
- 执行模式：`AUTO`

## 状态链

`ADVENTURE_CHAPTER` -> `STAGE_LIST` -> `FORMATION` -> `BATTLE` -> `VICTORY` -> `REWARD_OVERLAY` -> `STAGE_LIST`

## 已验证一轮操作

1. 冒险章节页点 `开始挑战`，坐标 `(850,1590)`。
2. 关卡列表点当前可挑战按钮。1-1 在 `(850,650)`，1-2 在 `(909,838)`。
3. 布阵页点 `出战`，坐标 `(715,1675)`。
4. 等待战斗和结算。
5. 结算页点 `确定`，坐标 `(540,1735)`。
6. 连续点击升级和奖励浮层，直到回到关卡列表。

设备 MCP 已用一段脚本完成 1-1 全流程，日志 marker 为 `CYCLE_DONE`，随后 1-1 显示为已通关，1-2 解锁。

## 关键发现

- 战斗页没有稳定节点树，必须依赖画面状态。
- 战斗动画期间 `waitStable` 可能超时，普通截图仍可用于确认。
- 关卡列表按钮的位置会随已通关条目变化，不能固定写死 y 坐标。
- 1-2 挑战按钮由 OCR 得出 bounds `(863,821)-(954,855)`，中心为 `(909,838)`。
- 结算后可能连续出现等级提升、角色获得或道具说明，需要多次关闭。
- 战斗耗时明显大于普通点击，探针等待时间应覆盖完整动画。
- **战斗内加速键（2026-10-01 晚补验）**：战斗页左下角圆形 `x1` 按钮中心约 `(85,1588)`，点击后变为 `x2`（战斗加速）；右下角还有个跳过/快进按钮（约 `(965,1560)`，未单独验证）。
- **自动连战（2026-10-01 晚补验）**：结算页有 `下一关`（约 `(722,1753)`）与 `开启自动挑战` 勾选框（约 `(630,1835)`）；勾选后自动连续战斗并跨章节保留，详见 `dupo-cangqiong-stage-progression.md`。
- 战力劣势（我方斗气低于敌方，如 21640 vs 26426）仍可能取胜，斗气数值只是参考；反之亦然。

## 可复跑脚本

`assets/probes/dupo-battle-cycle.example.js` 是 1-1 的完整一轮脚本。它证明了多状态固化路径，但也暴露了固定坐标限制：

- 当前脚本只适用于“最上方可挑战条目位于第一行”的情况。
- 下一轮应先 OCR 定位 `挑战`，再替换关卡按钮坐标。
- 建议生成项目把 `locate-challenge` 和 `tap-challenge` 拆成独立步骤，避免把关卡位置写死在主流程。

## 失败恢复

- 系统返回键会弹退出确认，必须点 `再玩会`。
- 应用重启后会回到登录页和活动弹窗，需要先关闭弹窗再进入游戏。
- 如果截图和输入同时超时，按设备恢复分级处理，不要无限重试点击。
