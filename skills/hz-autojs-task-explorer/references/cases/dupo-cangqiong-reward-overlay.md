# 斗破苍穹结算奖励弹层案例（reward overlay queue）

> 坐标说明：下文绝对坐标是 **1080×1920 基准空间** 的标定值。弹层关闭区应表达为 `edge: bottom-center`，且必须避开画面中间的可交互图标。

- 类型：画布 / 自绘型，多层奖励展示队列
- 设备：`device_android_e3bf91f528e0bbfe`，1080×1920
- 关联案例：`dupo-cangqiong-stage-progression.md`、`dupo-cangqiong-tutorial-chain.md`

> **2026-10-01 修正：** 本文早期把该层判定为「非交互遮挡层」，结论有误。实际是**可交互的多层弹层队列**，之所以看起来关不掉，是因为点击坐标恰好落在道具图标上，把详情层反复打开。正确处置见下文，判定方法见 `dupo-cangqiong-tutorial-chain.md`。

## 现象

1-3 / 1-4 / 1-5 结算点 `确定` 后，连续出现多层全屏奖励展示：

1. `等级提升` + `升级奖励` + 道具图标 + `点击屏幕关闭` 提示。
2. 道具详情面板：`紫晶卡`、`拥有数量`、说明文字。
3. 后续可能再出现 `解锁新功能`（如 `心火淬炼`、`境界`）。

## 关键结论（修正版）

- 该层**可以逐层关闭**，判定依据：点击 `(540,1690)` 底部提示区后，队列从道具详情推进到 `解锁新功能`，说明点击被正常消费。
- 失败原因在于**点击坐标落在可交互图标上**：`等级提升` 层里道具图标位于约 `(540,1490)`，点它会打开道具详情；再点详情任意处关闭，又回到 `等级提升` 层，于是形成 A↔B 循环。
- `success=true` 只代表输入事件下发成功，不代表目标应用消费了该事件；反过来，`success=true` 也不能直接推出"该层不可交互"。
- 判定「不可交互」之前，必须先排除点击点命中可交互元素这一可能。

## 状态识别

| 状态 | 锚点 | 说明 |
| --- | --- | --- |
| 升级顶层 A | `等级提升`、数字莲花、`升级奖励`、`点击屏幕关闭` | 道具图标约 `(540,1490)`，提示文字约 `(540,1670)` |
| 道具详情层 B | `紫晶卡`、`拥有数量`、物品说明 | 覆盖在 A 之上，点任意处关闭 |
| 功能解锁层 C | `解锁新功能`、功能名（`心火淬炼` / `境界`） | 队列最后阶段 |
| 业务层 | `第1章`、关卡 `1-1`…`1-7`、底部导航 | 目标状态 |

## 处置策略

1. 结算后等待完整动画，再截图判定当前是哪一层，不要立即连点。
2. 关闭时点击**底部提示区或空白区**（约 `(540,1690)`），避开画面中间的道具图标与按钮。
3. 每关闭一层后重新截图确认；若锚点在两个状态间来回切换，检查点击点是否命中了可交互图标。
4. 确认已避开可交互元素、且单次点击后锚点仍不变，才判定为疑似非交互层，此时才升级到等待 / 系统返回 / 重启应用。
5. 关闭过程中随时可能插入新的解锁提示层，需要把「未回到业务层」作为继续关闭的判据。
