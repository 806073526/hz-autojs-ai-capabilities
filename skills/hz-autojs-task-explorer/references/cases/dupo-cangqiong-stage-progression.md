- 类型：画布 / 自绘型，多关卡连续推进
- 设备：`device_android_e3bf91f528e0bbfe`，1080×1920，竖屏
- 执行模式：`AUTO`

## 状态链（本轮确认）

`CHAPTER_MAP` -> `STAGE_LIST` -> `FORMATION` -> `BATTLE` -> `VICTORY` -> `REWARD_OVERLAY` -> `STAGE_LIST`

与首轮相比，本轮补上了两个此前未覆盖的状态：

- `REWARD_OVERLAY`：结算之后的升级 / 道具说明全屏层，见 `dupo-cangqiong-reward-overlay.md`。

## 1-2 实际操作

1. 布阵页 OCR 读到 `上阵人数:1/6`，确认尚未满编。
2. OCR 定位 `若琳`，bounds `(312,1509)-(381,1541)`，中心取 `(347,1525)`。
3. 点击若琳卡片后复核，OCR 变为 `上阵人数:2/6`，证明上阵动作生效。
4. 点 `出战` `(722,1681)`，等待 24s。
5. 点结算 `确定` `(540,1735)`。
6. 连续点 `(540,1500)` 关闭升级和奖励浮层。
7. 日志 marker `STAGE12_DONE`，1-2 变为已通关。

## 1-3 实际操作

1. 清除残留弹层后回到章节地图，右下 `开始挑战` 中心约 `(855,1570)`。
2. 进入关卡列表，OCR 读到 `1-1 已通关`、`1-2 已通关`、`1-3` 带 `挑战`。
3. 1-3 `挑战` OCR bounds `(866,1023)-(956,1085)`，中心取 `(911,1054)`。
4. 布阵页 OCR 读到 `上阵人数:2/6`。直接点 `出战` 未推进，页面仍是 `FORMATION`。
5. 复点 `出战` 后进入 `BATTLE`，画面出现 `第1/15回合`。
6. 等待结算出现 `胜`、`全场最佳`、`获得奖励`、`确定`，点 `(540,1735)`。
7. 进入升级弹层，见遮挡型案例。

## 关键发现

**2026-10-01 补充：** 后续继续推进到 1-4、1-5 通关，挑战按钮继续下移：1-4 约 `(910,1172)`、1-5 约 `(912,1207)`。关卡列表会随已通关条目累积而滚动，`1-1` 会移出可视区，进一步说明必须用 OCR 动态定位。

- 同一按钮在不同进入时机可能失效：1-3 第一次点 `出战` 返回 true 但没有推进状态，复点才进入战斗。点击成功返回值不等于状态已转移。
- 关卡列表的 `挑战` 按钮位置随已通关条目数变化：1-1 `(850,650)`、1-2 `(909,838)`、1-3 `(911,1054)`。禁止写死行号或 y 坐标。
- 上阵动作有可观察反馈：`上阵人数:N/6`。探索时应优先找这类数值锚点，而不是依赖按钮高亮。
- 战斗状态可用 `第N/15回合` 作为运行时锚点。
- 结算状态可用 `胜`、`全场最佳`、`获得奖励` 组合锚点，比单看 `确定` 更稳。
- 关卡推进后底部六模块导航（城市 / 斗者 / 纳戒 / 势力 / 历练 / 冒险）仍在，说明结算完成回到了主界面框架。
- `device_run_script_text` 的脚本超时按 `timeoutMs` 计；`TASK_WAIT_TIMEOUT` 只代表等待超时，脚本可能仍在正常执行，必须查 `task_logs` 确认终态，不能据此判定失败。

- 章节地图右上角 `还差N关` 是**距下一个里程碑的剩余关卡数**，不是本章剩余数：第 1 章通关后显示 `还差10关`（对应 2-10 里程碑），2-1~2-9 通关过程中递减到 `还差1关`；2-10 通关并领取后切换为 `还差5关`（对应 3-5 里程碑）。里程碑奖励在右上角以 `可领取` 宝箱出现，点开面板后 `一键领取`，关闭流程与章节 1 相同。
- 章节通关后地图上出现 `下一章` 按钮（约 `(820,1552)`），可直接进入下一章地图。

## 胜利页快捷推进：`下一关` 与 `开启自动挑战`（2026-10-01 晚补验）

从 2-2 起，结算页除 `确定` 外新增两个推进控件（证据 `data/exploration/dupo-cangqiong-20261001/screenshots/118-*` 起）：

| 控件 | 位置（1080×1920 标定） | 行为 |
| --- | --- | --- |
| `下一关` | 中心约 `(722,1753)`，与 `确定` 并排 | 不经关卡列表，直接完成下一关并回到结算页 |
| `开启自动挑战` | 文字 bounds `(658,1816)-(889,1853)`，勾选框在其左约 `(630,1835)` | 勾选后自动连续挑战后续关卡 |

实测链路（2-2 结算页起）：

```text
2-2 结算 → 点 `下一关`
  → 2-3 结算出现（奖励 660/2152/389，与本关首通一致）
  → 勾选 `开启自动挑战`
  → 2-4 / 2-5 / 2-6 / 2-7 / 2-8 连续自动战斗（期间插入 14 级升级弹层）
  → 2-9 结算（此时页面只剩 `确定`，自动链已结束）
```

结束后回到章节地图，进度由 `还差9关` 推进到 `还差1关`。

**待验证：**

- 勾选状态跨战斗、跨章节保留（本轮已验证：第 2 章勾选后第 3 章仍自动连打）；是否跨会话（重启后）保留未验证。

## 可复跑脚本

`assets/probes/dupo-stage-progression.example.js` 固化了「进关卡列表 -> 挑战 -> 布阵 -> 出战 -> 结算」骨架，挑战坐标和上阵步骤留作参数，避免把当前关卡位置写死。

## 失败恢复

- `出战` 后画面未变化：先截图确认是否仍在布阵页，再复点一次；不要连续快速点，避免叠加弹层。
- 结算 `确定` 后出现多层浮层：进入遮挡型案例的处置流程。
- 连续 `TASK_WAIT_TIMEOUT`：改查 `task_logs`，确认脚本是否已自报终态。
- 关卡列表 `挑战` OCR 未命中：重新截图确认是否停在章节地图而非关卡列表。
